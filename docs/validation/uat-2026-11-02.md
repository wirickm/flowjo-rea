# Front-end acceptance test and fix decisions (2026-11-02)

This record explains **why** each fix from the 2026-11-02 acceptance test was
made the way it was. For each defect it names what FlowJo 10.6.2 does (from
static reading, specs section 6), the decision, the reason, and the test that
holds it in place.

## 1. Test (FJR-UAT-01)

- Method: five operators used the app through a real Chromium browser. They
  read labels and screenshots and clicked, dragged and typed like a user; no
  internal APIs were called.
- Datasets: D1 8-color ICS FCS (3 files); D2 FlowJo 10 `.wsp` workspaces; D3
  ISAC Gating-ML 2.0 set; D4 matrix CSVs, single-stain controls, spectral
  CSVs; D5 noncompliant, multi-data-set and older FCS; synthetic cell cycle
  and proliferation data.
- Result: 234 controls tested, 153 pass, 24 fail, 56 observations, 1 not
  reached; no crashes and no uncaught page errors.
- Severity: S1 crash or data loss, S2 feature broken, S3 minor or wrong
  output, S4 cosmetic.

## 2. FlowJo investigation (REA method)

Each defect became a question in `rea-investigation-checklist.md` (Q12 to
Q18). Evidence came from the verified FlowJo 10.6.2 installer (SHA-256
`90721621...`, same as `tools/rea-originals.json`): `javap` of the Java
classes (names, signatures, constants) and the native engine's symbols.
Behaviors are written in our own words in specs section 6. No FlowJo code,
bytecode listing or disassembly is in the repository. FlowJo was not run
(macOS only), so runtime behavior stays unconfirmed (checklist Q10).

Decision rule:
- **Match FlowJo** when FlowJo has a clear behavior. This app targets FlowJo
  10 compatibility.
- **Own rule** when FlowJo has no such feature. This app chooses, and says
  so.
- **Stricter than FlowJo** when FlowJo's behavior loses work or hides a
  problem, and a safer rule changes no FlowJo-compatible result.

Validation after step 1: `npx tsc -p .` clean; `npm test` 215 passed, 2
skipped; `npm run e2e` all checks pass (cell cycle now 55.5 / 29.2 / 15.3
against truth 55 / 30 / 15). `src/core/wsp.ts` is an REA owner file, so the
REA ledger was regenerated (`docs/obligation-ledger.md`).

Known limit found during the fix: polygons and ellipses imported from .wsp
use FlowJo's gate grid, which Gating-ML cannot express. They export as exact
shapes, so their counts can differ after a Gating-ML round trip (specs 6.5).

input checks on matrix files and cells (FlowJo accepts bad files silently),
